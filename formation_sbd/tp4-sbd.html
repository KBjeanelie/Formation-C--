Séance 4 — 4 heures

Projet : Modélisation & Synthèse

Pour clôturer cette initiation, vous allez concevoir la base de données d'une application E-Commerce de A à Z. C'est l'heure du grand test final !

1. Exercice Guidé : Modélisation du E-Commerce

Le client vous demande de créer une base de données pour sa nouvelle boutique en ligne. Il a besoin de :

  • Stocker les informations des Clients (Nom, email, date d'inscription).
  • Stocker le catalogue de Produits (Nom, prix, stock disponible).
  • Garder une trace des Commandes (Quelle commande, passée par quel client, et quand).
  • Savoir quels produits ont été achetés dans quelle commande (Lignes de Commande).

Comment transformer cela en SQL (Le Schéma)

Voici la réflexion que vous devez avoir avant même de taper du code :

  • clients : ID, nom, email (unique), date_inscription.
  • produits : ID, nom, prix, stock.
  • commandes : ID, client_id (Clé Etrangère), date_commande.
  • lignes_commande : commande_id (Clé Etrangère), produit_id (Clé Etrangère), quantite_achetee.
Attention à l'ordre de création ! Vous ne pouvez pas créer la table commandes avant la table clients, car la première a besoin de la seconde pour sa clé étrangère. L'ordre logique est toujours de créer les tables "indépendantes" en premier.

2. Travaux Pratiques (10 exercices)

À vous de jouer. Mettez en pratique tout ce que vous avez appris lors des 3 premières séances pour réaliser ce projet de e-commerce.

TP 01

Préparer l'environnement

Créez une base de données nommée ecommerce_db et sélectionnez-la.

▶ Voir la solution 
CREATE DATABASE ecommerce_db;
USE ecommerce_db;
TP 02

Créer les tables indépendantes

Créez la table clients (avec une contrainte UNIQUE sur l'email) et la table produits (avec une contrainte CHECK pour s'assurer que le prix est toujours positif ou nul).

▶ Voir la solution 
CREATE TABLE clients (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nom VARCHAR(100) NOT NULL,
    email VARCHAR(150) UNIQUE NOT NULL,
    date_inscription DATE DEFAULT (CURRENT_DATE)
);

CREATE TABLE produits (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nom VARCHAR(100) NOT NULL,
    prix DECIMAL(10,2) CHECK (prix >= 0),
    stock INT DEFAULT 0
);
TP 03

Créer les tables dépendantes

Créez la table commandes et la table de liaison lignes_commande en n'oubliant pas les FOREIGN KEYS.

▶ Voir la solution 
CREATE TABLE commandes (
    id INT AUTO_INCREMENT PRIMARY KEY,
    client_id INT,
    date_commande DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (client_id) REFERENCES clients(id)
);

CREATE TABLE lignes_commande (
    commande_id INT,
    produit_id INT,
    quantite INT DEFAULT 1,
    PRIMARY KEY (commande_id, produit_id), -- Clé primaire composite
    FOREIGN KEY (commande_id) REFERENCES commandes(id),
    FOREIGN KEY (produit_id) REFERENCES produits(id)
);
TP 04

Peupler les bases (Jeu de test)

Insérez 2 clients et 3 produits dans la base de données.

▶ Voir la solution 
INSERT INTO clients (nom, email) VALUES 
('Alice Dubois', 'alice@email.com'),
('Bob Martin', 'bob@email.com');

INSERT INTO produits (nom, prix, stock) VALUES 
('Ordinateur Portable', 999.99, 10),
('Souris Sans Fil', 25.50, 50),
('Clavier Mécanique', 80.00, 20);
TP 05

Simulation d'un achat

Bob (client 2) décide d'acheter aujourd'hui 1 Ordinateur (produit 1) et 2 Souris (produit 2). Créez la commande, puis les deux lignes de commande associées.

▶ Voir la solution 
-- 1. On crée le bon de commande pour Bob
INSERT INTO commandes (client_id) VALUES (2);
-- (Supposons que cette commande a reçu l'ID 1 car c'est la toute première)

-- 2. On ajoute les produits dans cette commande n°1
INSERT INTO lignes_commande (commande_id, produit_id, quantite) VALUES 
(1, 1, 1),  -- 1 Ordinateur
(1, 2, 2);  -- 2 Souris
TP 06

Mise à jour des stocks

Suite à l'achat de Bob, mettez à jour la table des produits pour déduire les quantités achetées du stock.

▶ Voir la solution 
UPDATE produits SET stock = stock - 1 WHERE id = 1; -- Ordinateur
UPDATE produits SET stock = stock - 2 WHERE id = 2; -- Souris
TP 07

Afficher la facture (Jointure complexe)

Écrivez une requête avec des INNER JOIN pour afficher le détail de la commande de Bob : Nom du client, Date de commande, Nom du produit acheté, Quantité, et Prix unitaire.

▶ Voir la solution 
SELECT c.nom AS Client, cmd.date_commande, p.nom AS Produit, lc.quantite, p.prix
FROM commandes cmd
INNER JOIN clients c ON cmd.client_id = c.id
INNER JOIN lignes_commande lc ON cmd.id = lc.commande_id
INNER JOIN produits p ON lc.produit_id = p.id
WHERE cmd.id = 1;
TP 08

Calcul du Total d'une commande (Agrégation)

En utilisant la requête précédente, calculez le montant total que Bob doit payer (Somme des prix multipliés par les quantités).

▶ Voir la solution 
SELECT SUM(p.prix * lc.quantite) AS Total_A_Payer
FROM commandes cmd
INNER JOIN lignes_commande lc ON cmd.id = lc.commande_id
INNER JOIN produits p ON lc.produit_id = p.id
WHERE cmd.id = 1;
TP 09

Valeur du stock actuel

Le comptable veut connaître la valeur totale de notre stock actuel (pour tous les produits, prix * stock). Écrivez la requête.

▶ Voir la solution 
SELECT SUM(prix * stock) AS Valeur_Total_Stock
FROM produits;
TP 10

Félicitations ! Export du schéma

Pour terminer, écrivez la commande MySQL (à taper dans le terminal) qui permet de sauvegarder toute votre base (structure et données) dans un fichier backup.sql pour l'envoyer au client.

▶ Voir la solution 
-- Cette commande ne se tape pas dans MySQL, mais dans le terminal (invite de commandes) !
mysqldump -u root -p ecommerce_db > backup.sql
