Installer et configurer C++ — Windows, macOS, Linux

Un seul objectif final quel que soit le système : pouvoir taper g++ main.cpp -o main puis ./main dans un terminal, ou obtenir l'équivalent dans un IDE.

Bonjour, C++ !
01

Windows

Deux approches courantes : installer un compilateur natif (MinGW-w64), ou utiliser Linux via WSL.

Option A — MinGW-w64 (recommandé pour débuter)

  1. Télécharger MinGW-w64 depuis winlibs.com (version "UCRT runtime" recommandée) ou via l'installateur MSYS2.
  2. Extraire l'archive, par exemple dans C:\mingw64.
  3. Ajouter C:\mingw64\bin à la variable d'environnement PATH : Paramètres → Système → Informations système → Paramètres système avancés → Variables d'environnement → modifier Path.
  4. Ouvrir une nouvelle invite de commandes (obligatoire pour que le PATH soit pris en compte) et vérifier :
g++ --version

Option B — WSL (Windows Subsystem for Linux)

Fait tourner un vrai environnement Linux dans Windows — pratique si vous suivez aussi des cours orientés Linux/serveur.

## dans PowerShell, en administrateur
wsl --install

## puis, une fois dans le terminal Linux ouvert
sudo apt update
sudo apt install g++
Quel choix ? MinGW-w64 si vous voulez rester dans l'environnement Windows habituel (Explorateur, VS Code natif). WSL si vous êtes à l'aise avec un terminal Linux ou si le reste de la formation utilise des outils Linux.
02

macOS

macOS fournit un compilateur (Clang, compatible avec les commandes g++) via les outils en ligne de commande d'Xcode.
xcode-select --install

Une fenêtre propose l'installation des "Command Line Tools" — valider et attendre la fin du téléchargement. Vérifier ensuite :

g++ --version
À savoir : sur macOS, la commande g++ pointe en réalité vers Clang, pas vers le vrai GCC. Pour la quasi-totalité d'un cours de C++, c'est totalement transparent. Pour obtenir le "vrai" GCC (rarement nécessaire), on peut installer Homebrew puis brew install gcc.
03

Linux

La commande d'installation dépend du gestionnaire de paquets de la distribution.
DistributionCommande
Debian / Ubuntusudo apt install build-essential
Fedorasudo dnf install gcc-c++
Arch / Manjarosudo pacman -S base-devel
openSUSEsudo zypper install gcc-c++

build-essential et base-devel installent d'un coup g++, make et les autres outils de compilation habituels. Vérifier ensuite :

g++ --version
04

Éditeurs et IDE

Le compilateur suffit pour coder en ligne de commande ; un éditeur ou un IDE rend l'écriture et le débogage plus confortables. Fonctionnent à l'identique sur Windows, macOS et Linux.
Visual Studio Code

Léger, gratuit, multiplateforme. Installer l'extension C/C++ (Microsoft) et éventuellement Code Runner pour exécuter un fichier en un clic.

Code::Blocks

IDE dédié au C/C++, léger. Choisir la version "with MinGW" sur Windows pour avoir un compilateur préconfiguré directement dans l'installateur.

CLion

IDE complet de JetBrains, très puissant pour de gros projets, payant (gratuit avec une licence étudiante).

Terminal + éditeur de texte

Aucune installation d'IDE : n'importe quel éditeur (VS Code, Sublime, vim...) pour écrire le code, puis g++ en ligne de commande pour compiler.

Configurer VS Code pour compiler avec un raccourci

Dans le dossier du projet, créer .vscode/tasks.json :

{
  "version": "2.0.0",
  "tasks": [
    {
      "label": "compiler",
      "type": "shell",
      "command": "g++",
      "args": ["${file}", "-o", "${fileDirname}/${fileBasenameNoExtension}"]
    }
  ]
}

Ensuite, Ctrl+Shift+B (ou Cmd+Shift+B sur Mac) compile le fichier actuellement ouvert.

Sans rien installer

Utile pour tester rapidement un extrait de code, ou si l'installation locale pose problème pendant une séance.
ServiceAvantage
godbolt.orgVoir le code assembleur généré, plusieurs compilateurs/versions au choix
replit.comEnvironnement complet avec fichiers multiples, proche d'un vrai projet
onlinegdb.comDébogueur intégré simple, bon pour visualiser l'exécution pas à pas
Limite à connaître : ces services ne remplacent pas une installation locale pour la séance sur les fichiers (lecture/écriture sur disque), où l'accès au système de fichiers réel est nécessaire.
06

Vérifier son installation

Ce test doit réussir quel que soit le système ou le logiciel choisi ci-dessus.

Créer un fichier test.cpp :

#include <iostream>

int main() {
    std::cout << "Configuration OK" << std::endl;
    return 0;
}

Puis, dans un terminal ouvert dans le même dossier :

g++ test.cpp -o test
./test
Résultat attendu : le terminal affiche Configuration OK. Si c'est le cas, l'environnement est prêt pour toutes les séances du TP.
Sur Windows sans WSL : l'exécutable s'appelle test.exe et se lance avec test ou .\test plutôt que ./test.
07

Dépannage

Les erreurs les plus fréquentes en début de formation, indépendamment du système.
« g++ n'est pas reconnu » / « command not found »
Le compilateur n'est pas installé, ou son dossier n'est pas dans le PATH. Sur Windows, vérifier l'ajout du dossier bin de MinGW au PATH et rouvrir le terminal. Sur macOS/Linux, relancer l'installation correspondante (sections 02 et 03).
« Permission denied » en lançant ./main
Sur macOS/Linux, l'exécutable a besoin du droit d'exécution : 
chmod +x main
./main
Le programme compile mais rien ne s'affiche
Vérifier qu'on exécute bien le fichier fraîchement compilé (./main), et pas une ancienne version. Vérifier aussi que std::cout est bien suivi de std::endl ou que le programme atteint bien return 0; à la fin.
VS Code ne reconnaît pas #include <iostream> (souligné en rouge)
C'est un avertissement de l'extension C/C++, pas une erreur de compilation. Ouvrir la palette de commandes (Ctrl+Shift+P) → C/C++: Edit Configurations et vérifier que le compilateur détecté correspond bien à celui installé (MinGW, Clang...).
Erreur liée aux accents ou à l'affichage sur Windows (caractères bizarres)
Le terminal Windows n'utilise pas UTF-8 par défaut. Ajouter en tout début de main() : 
system("chcp 65001 > nul");
ou lancer le programme depuis un terminal déjà configuré en UTF-8 (Windows Terminal récent, ou WSL).
