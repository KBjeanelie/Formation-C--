Guide de Survie

Cheatsheet PostgreSQL

Un aide-mémoire complet pour retrouver ses marques de 0 à expert. Idéal pour se rafraîchir la mémoire avant de démarrer la Séance 1.

1. Les Méta-commandes psql (Terminal)

Si vous utilisez l'outil en ligne de commande psql, ces commandes "antislash" sont indispensables :

  • \l : Lister toutes les bases de données.
  • \c ma_base : Se connecter à la base "ma_base" (comme USE ma_base sous MySQL).
  • \dt : Lister toutes les tables de la base actuelle.
  • \d ma_table : Décrire la structure d'une table précise (colonnes, types, index).
  • \dn : Lister les schémas.
  • \du : Lister les rôles et utilisateurs.
  • \q : Quitter psql.

2. Bases de Données et Schémas

Contrairement à MySQL, une instance PostgreSQL contient plusieurs Bases de données, et chaque Base contient plusieurs Schémas (espaces de noms). Le schéma par défaut s'appelle public.

-- Créer une base de données
CREATE DATABASE e_commerce;

-- (Pensez à vous y connecter ensuite : \c e_commerce)

-- Créer un nouveau schéma pour organiser ses tables
CREATE SCHEMA compta;

-- Utiliser explicitement un schéma :
CREATE TABLE compta.factures (id SERIAL);

3. Création de Tables & Types de base

PostgreSQL est strictement typé. L'auto-incrémentation se fait via le type magique SERIAL (qui crée une séquence en arrière-plan).

CREATE TABLE employes (
    id SERIAL PRIMARY KEY,             -- Auto-incrément (1, 2, 3...)
    nom VARCHAR(100) NOT NULL,         -- Chaîne avec limite
    bio TEXT,                          -- Chaîne sans limite (plus performant que VARCHAR)
    age INT CHECK (age >= 18),         -- Entier avec contrainte
    salaire DECIMAL(10,2),             -- Décimal précis (10 chiffres total, 2 après virgule)
    is_active BOOLEAN DEFAULT TRUE,    -- Vrai booléen (TRUE / FALSE)
    date_embauche TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

4. Clés Étrangères (Relations)

Lier deux tables ensemble et définir le comportement en cas de suppression.

CREATE TABLE departements (
    id SERIAL PRIMARY KEY,
    nom VARCHAR(50)
);

CREATE TABLE employes (
    id SERIAL PRIMARY KEY,
    nom VARCHAR(100),
    departement_id INT REFERENCES departements(id) ON DELETE CASCADE
);
-- ON DELETE CASCADE : Si on supprime un département, 
-- tous ses employés sont supprimés automatiquement.

5. Opérations CRUD (Manipulation des données)

Insertion (CREATE)

INSERT INTO employes (nom, age, salaire) 
VALUES ('Alice', 30, 2500.50),
       ('Bob', 25, 2100.00)
RETURNING id; -- Astuce PG: Récupère l'ID généré immédiatement

Lecture (READ)

SELECT nom, salaire FROM employes 
WHERE age >= 25 
ORDER BY salaire DESC 
LIMIT 10 OFFSET 5; -- Pagination

Mise à jour (UPDATE)

UPDATE employes 
SET salaire = salaire + 100, is_active = TRUE 
WHERE nom = 'Bob';

Suppression (DELETE)

DELETE FROM employes WHERE is_active = FALSE;

6. Modifier une structure existante (ALTER TABLE)

Il arrive souvent de devoir modifier une table après sa création.

-- Ajouter une colonne
ALTER TABLE employes ADD COLUMN email VARCHAR(150);

-- Renommer une colonne
ALTER TABLE employes RENAME COLUMN nom TO nom_complet;

-- Modifier le type d'une colonne (attention aux données existantes)
ALTER TABLE employes ALTER COLUMN salaire TYPE NUMERIC(12,2);

-- Supprimer une colonne
ALTER TABLE employes DROP COLUMN bio;

7. Les Jointures de base (Rappel)

Pour récupérer des données réparties dans plusieurs tables.

SELECT employes.nom, departements.nom AS nom_dep
FROM employes
INNER JOIN departements ON employes.departement_id = departements.id;
-- LEFT JOIN : Garde les employés même s'ils n'ont pas de département
-- RIGHT JOIN : Garde les départements même sans employés

8. Gestion des Utilisateurs et Droits (Sécurité)

PostgreSQL utilise le concept de "Rôles" qui peuvent agir comme des utilisateurs (avec mot de passe) ou des groupes de permissions.

Créer et modifier des rôles

-- Créer un utilisateur pouvant se connecter
CREATE ROLE dev WITH LOGIN PASSWORD 'secret123';

-- Créer un rôle "groupe" (sans mot de passe)
CREATE ROLE lecteurs;

-- Ajouter l'utilisateur "dev" au groupe "lecteurs"
GRANT lecteurs TO dev;

-- Donner les droits d'administrateur (Superuser)
ALTER ROLE dev WITH SUPERUSER;

Gérer les permissions (GRANT / REVOKE)

-- 1. Donner l'accès au schéma
GRANT USAGE ON SCHEMA public TO lecteurs;

-- 2. Donner le droit de lecture sur TOUTES les tables du schéma
GRANT SELECT ON ALL TABLES IN SCHEMA public TO lecteurs;

-- Donner des droits spécifiques sur une table précise
GRANT INSERT, UPDATE ON employes TO dev;

-- Retirer (révoquer) un droit
REVOKE UPDATE ON employes FROM dev;
