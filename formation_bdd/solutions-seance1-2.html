Livre des Solutions : PostgreSQL Avancé

Corrections détaillées des 15 exercices (Séances 1 & 2)

Niveau Facile : Les bases de PL/pgSQL

Solution 1 : Premier Bloc Anonyme

DO $$
DECLARE
    nom VARCHAR := 'Alice';
BEGIN
    RAISE NOTICE 'Bonjour % !', nom;
END;
$$;
Explication : Un bloc anonyme n'est pas sauvegardé en base (contrairement à une fonction). Il commence par DO $$. La section DECLARE sert à initialiser les variables, et le code s'écrit entre BEGIN et END;. Le % dans RAISE NOTICE agit comme un espace réservé (placeholder) pour la variable.

Solution 2 : Structure Conditionnelle (IF/ELSE)

DO $$
DECLARE
    note INT := 14;
BEGIN
    IF note >= 10 THEN
        RAISE NOTICE 'Validé';
    ELSE
        RAISE NOTICE 'Non validé';
    END IF;
END;
$$;
Explication : La structure IF est très classique. Ne pas oublier de terminer systématiquement par END IF; (avec l'espace).

Solution 3 : La Boucle FOR

DO $$
BEGIN
    FOR i IN 1..10 LOOP
        RAISE NOTICE '7 x % = %', i, (7 * i);
    END LOOP;
END;
$$;
Explication : En PL/pgSQL, la boucle for sur des entiers s'écrit FOR variable IN debut..fin LOOP. Nul besoin de déclarer la variable i dans la section DECLARE, elle est créée automatiquement par la boucle.

Solution 4 : Ma première Fonction

CREATE OR REPLACE FUNCTION multiplier(a INT, b INT) 
RETURNS INT AS $$
BEGIN
    RETURN a * b;
END;
$$ LANGUAGE plpgsql;

-- Test :
SELECT multiplier(5, 4);
Explication : Pour créer une fonction, il faut préciser les paramètres, le type de retour (RETURNS INT) et surtout spécifier le langage utilisé à la toute fin (LANGUAGE plpgsql). Le mot clé RETURN arrête l'exécution de la fonction et renvoie la valeur.

Solution 5 : Fonction texte simple

CREATE OR REPLACE FUNCTION saluer(nom VARCHAR) 
RETURNS VARCHAR AS $$
BEGIN
    IF nom IS NULL THEN
        RETURN 'Bonjour, inconnu';
    ELSE
        RETURN 'Bonjour, ' || nom;
    END IF;
END;
$$ LANGUAGE plpgsql;
Explication : En SQL, l'opérateur de concaténation de chaînes est le double tube ||. La gestion du NULL est cruciale car concaténer une chaîne avec NULL retourne toujours NULL ! L'utilisation du IF ou de la fonction COALESCE() permet d'éviter ce piège.

Niveau Intermédiaire : Manipulation de données et Triggers simples

Solution 6 : Formatage avant insertion (Trigger)

CREATE OR REPLACE FUNCTION trg_format_nom() 
RETURNS TRIGGER AS $$
BEGIN
    NEW.nom := UPPER(NEW.nom);
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trigger_maj_nom
BEFORE INSERT ON produits
FOR EACH ROW
EXECUTE FUNCTION trg_format_nom();
Explication : Un trigger s'écrit toujours en deux temps sous PostgreSQL : 1. La fonction (qui doit retourner TRIGGER). 2. Le rattachement à la table. Puisque c'est un trigger BEFORE, on peut modifier les valeurs entrantes (qui se trouvent dans la variable spéciale NEW) avant que Postgres ne les écrive sur le disque.

Solution 7 : Validation des données (RAISE EXCEPTION)

CREATE OR REPLACE FUNCTION trg_valider_prix() 
RETURNS TRIGGER AS $$
BEGIN
    IF NEW.prix <= 0 THEN
        RAISE EXCEPTION 'Le prix doit être strictement positif';
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trigger_check_prix
BEFORE INSERT OR UPDATE ON produits
FOR EACH ROW
EXECUTE FUNCTION trg_valider_prix();
Explication : La commande RAISE EXCEPTION stoppe instantanément la transaction en cours. Si le prix est invalide, l'INSERT ou l'UPDATE échouera et une erreur sera renvoyée à l'application cliente. C'est idéal pour garantir l'intégrité métier des données !

Solution 8 : Boucle sur un résultat de requête (Record)

DO $$
DECLARE
    ligne RECORD;
BEGIN
    FOR ligne IN (SELECT nom, stock FROM produits WHERE stock < 10) 
    LOOP
        RAISE NOTICE 'Alerte stock : % (Reste: %)', ligne.nom, ligne.stock;
    END LOOP;
END;
$$;
Explication : Une variable RECORD (enregistrement) est un type générique qui peut contenir une ligne entière d'un résultat de requête. La boucle va exécuter le SELECT, puis itérer sur chaque ligne retournée. On accède aux colonnes avec la syntaxe variable.colonne.

Solution 9 : Fonction retournant plusieurs valeurs

CREATE OR REPLACE FUNCTION get_produits_chers(seuil DECIMAL) 
RETURNS TABLE (nom VARCHAR, prix DECIMAL) AS $$
BEGIN
    RETURN QUERY 
    SELECT p.nom, p.prix FROM produits p WHERE p.prix > seuil;
END;
$$ LANGUAGE plpgsql;

-- Utilisation :
SELECT * FROM get_produits_chers(50.00);
Explication : RETURNS TABLE (...) permet de définir la structure du tableau renvoyé par la fonction. L'instruction RETURN QUERY exécute la requête qui la suit et ajoute son résultat à l'ensemble retourné par la fonction. Contrairement à RETURN simple, RETURN QUERY ne stoppe pas l'exécution de la fonction !

Solution 10 : Journalisation des suppressions (Audit)

CREATE OR REPLACE FUNCTION trg_audit_delete() 
RETURNS TRIGGER AS $$
BEGIN
    INSERT INTO audit_produits (nom, date_suppression)
    VALUES (OLD.nom, NOW());
    
    RETURN OLD; -- Pour un AFTER DELETE, le return n'a pas d'importance, mais OLD est conseillé.
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trigger_audit_delete
AFTER DELETE ON produits
FOR EACH ROW
EXECUTE FUNCTION trg_audit_delete();
Explication : La variable spéciale OLD contient l'état de la ligne AVANT sa modification ou suppression. Puisque la donnée vient d'être supprimée de la table source, nous l'insérons dans une table d'archive pour conserver une trace (Audit).

Niveau Difficile : Cas concrets et logiques avancées

Solution 11 : Gestion des exceptions (Try/Catch)

DO $$
DECLARE
    resultat DECIMAL;
BEGIN
    resultat := 10 / 0;
EXCEPTION
    WHEN division_by_zero THEN
        RAISE NOTICE 'Erreur mathématique détectée !';
END;
$$;
Explication : Sans le bloc EXCEPTION, la transaction aurait lamentablement échoué (rollback complet). Le bloc EXCEPTION permet de capturer l'erreur (ici via le code SQLSTATE d'erreur division_by_zero) et de la traiter gracieusement.

Solution 12 : Fonction de Virement Transactionnel

CREATE OR REPLACE FUNCTION virement(src INT, dst INT, mnt DECIMAL) 
RETURNS VOID AS $$
DECLARE
    solde_source DECIMAL;
BEGIN
    -- 1. Lire le solde
    SELECT solde INTO solde_source FROM comptes WHERE id = src FOR UPDATE;
    
    -- 2. Vérifier
    IF solde_source < mnt THEN
        RAISE EXCEPTION 'Solde insuffisant (%). Demande: %', solde_source, mnt;
    END IF;
    
    -- 3. Effectuer le virement
    UPDATE comptes SET solde = solde - mnt WHERE id = src;
    UPDATE comptes SET solde = solde + mnt WHERE id = dst;
END;
$$ LANGUAGE plpgsql;
Explication : La fonction SELECT ... INTO variable est indispensable pour extraire une valeur de la base et la manipuler en PL/pgSQL. (Note avancée : Le FOR UPDATE pose un verrou exclusif sur la ligne pour éviter les problèmes de concurrence si deux virements se font à la même milliseconde).

Solution 13 : Empêcher la modification de données sensibles

CREATE OR REPLACE FUNCTION trg_lock_nom() 
RETURNS TRIGGER AS $$
BEGIN
    IF NEW.titulaire IS DISTINCT FROM OLD.titulaire THEN
        RAISE EXCEPTION 'Changement de propriétaire interdit';
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trigger_lock_nom
BEFORE UPDATE ON comptes
FOR EACH ROW
EXECUTE FUNCTION trg_lock_nom();
Explication : IS DISTINCT FROM est une version améliorée de l'opérateur d'inégalité !=. Sa force est qu'il compare correctement les valeurs NULL (car en SQL, "NULL != NULL" ne renvoie ni vrai ni faux, mais NULL !). Il permet d'être certain que la valeur a physiquement changé.

Solution 14 : Maintien d'un total (Denormalisation)

CREATE OR REPLACE FUNCTION trg_maj_statistiques() 
RETURNS TRIGGER AS $$
BEGIN
    IF TG_OP = 'INSERT' THEN
        UPDATE statistiques SET total_fonds = total_fonds + NEW.solde;
    ELSIF TG_OP = 'UPDATE' THEN
        UPDATE statistiques SET total_fonds = total_fonds - OLD.solde + NEW.solde;
    ELSIF TG_OP = 'DELETE' THEN
        UPDATE statistiques SET total_fonds = total_fonds - OLD.solde;
    END IF;
    
    RETURN NULL; -- Pour un trigger AFTER, return NULL est standard
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_stats
AFTER INSERT OR UPDATE OR DELETE ON comptes
FOR EACH ROW
EXECUTE FUNCTION trg_maj_statistiques();
Explication : Un même trigger peut s'abonner à plusieurs événements (INSERT OR UPDATE OR DELETE). La variable spéciale TG_OP permet de savoir l'action déclenchante pour ajuster la somme globale intelligemment. Ce modèle évite de faire un "SELECT SUM()" coûteux sur des tables géantes.

Solution 15 : SQL Dynamique avec EXECUTE

CREATE OR REPLACE FUNCTION compter_lignes(nom_table VARCHAR) 
RETURNS INT AS $$
DECLARE
    total INT;
BEGIN
    -- Exécution d'une chaîne SQL construite dynamiquement
    EXECUTE format('SELECT COUNT(*) FROM %I', nom_table) INTO total;
    RETURN total;
END;
$$ LANGUAGE plpgsql;
Explication : Les identifiants SQL (noms de tables ou colonnes) ne peuvent pas être des variables standards dans une requête. Nous sommes obligés de construire une chaîne de caractères et de l'exécuter avec EXECUTE. La fonction format() avec le paramètre %I protège contre l'injection SQL en gérant les guillemets automatiquement.
