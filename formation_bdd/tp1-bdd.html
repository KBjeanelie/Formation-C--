Séance 1

PL/pgSQL : Procédures & Triggers

L'objectif de cette séance est de déporter la logique métier (calculs, vérifications, historisation) directement dans le moteur de base de données PostgreSQL.

Introduction (Théorie - 15 min)

Le PL/pgSQL (Procedural Language/PostgreSQL) ajoute des éléments de programmation (variables, boucles, conditions) au SQL classique.

  • Fonction : Retourne une valeur. Utilisée pour des calculs.
  • Procédure (depuis PG 11) : Ne retourne rien, mais peut exécuter des transactions complètes.
  • Trigger : Une fonction qui s'exécute automatiquement AVANT ou APRÈS un INSERT/UPDATE/DELETE.

Préparation : Base E-Commerce

Exécutez ce script pour créer les tables de notre TP :

CREATE TABLE clients (
    id SERIAL PRIMARY KEY,
    nom VARCHAR(100),
    points_fidelite INT DEFAULT 0
);

CREATE TABLE produits (
    id SERIAL PRIMARY KEY,
    nom VARCHAR(100),
    prix DECIMAL(10,2),
    stock INT
);

CREATE TABLE commandes (
    id SERIAL PRIMARY KEY,
    client_id INT REFERENCES clients(id),
    produit_id INT REFERENCES produits(id),
    quantite INT,
    date_commande TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

TP 1 : La Fonction de Réduction

Objectif : Créer une fonction calculer_reduction(client_id) qui retourne un pourcentage de réduction. Si le client a plus de 100 points, il a 10% de réduction, sinon 0%.
Voir la solution 
CREATE OR REPLACE FUNCTION calculer_reduction(p_client_id INT) 
RETURNS DECIMAL AS $$
DECLARE
    v_points INT;
    v_reduction DECIMAL;
BEGIN
    -- Récupération des points
    SELECT points_fidelite INTO v_points 
    FROM clients WHERE id = p_client_id;
    
    -- Logique
    IF v_points >= 100 THEN
        v_reduction := 0.10; -- 10%
    ELSE
        v_reduction := 0.00;
    END IF;
    
    RETURN v_reduction;
END;
$$ LANGUAGE plpgsql;

-- Test de la fonction :
SELECT nom, calculer_reduction(id) FROM clients;

TP 2 : La Procédure d'Achat

Objectif : Créer une procédure valider_commande(p_client, p_produit, p_qte) qui insère la commande ET déduit le stock.
Voir la solution 
CREATE OR REPLACE PROCEDURE valider_commande(
    p_client INT, p_produit INT, p_qte INT
) AS $$
BEGIN
    -- 1. Insérer la commande
    INSERT INTO commandes (client_id, produit_id, quantite) 
    VALUES (p_client, p_produit, p_qte);
    
    -- 2. Mettre à jour le stock
    UPDATE produits 
    SET stock = stock - p_qte 
    WHERE id = p_produit;
    
    -- Le COMMIT est implicite dans une procédure appelée correctement
END;
$$ LANGUAGE plpgsql;

-- Test :
CALL valider_commande(1, 1, 1);
SELECT * FROM produits; -- Le stock de Laptop doit être à 4

TP 3 : Le Trigger Anti-Rupture

Objectif : Créer un Trigger qui se déclenche AVANT la mise à jour d'un produit. Si le nouveau stock est inférieur à 0, il lève une exception pour bloquer la transaction.
Voir la solution

Un trigger nécessite d'abord une fonction de type TRIGGER :

CREATE OR REPLACE FUNCTION verifier_stock()
RETURNS TRIGGER AS $$
BEGIN
    -- NEW représente la nouvelle ligne (après UPDATE)
    IF NEW.stock < 0 THEN
        RAISE EXCEPTION 'Stock insuffisant pour le produit % !', NEW.nom;
    END IF;
    
    RETURN NEW; -- Obligatoire pour un trigger BEFORE
END;
$$ LANGUAGE plpgsql;

-- Attacher la fonction à la table
CREATE TRIGGER trg_check_stock
BEFORE UPDATE ON produits
FOR EACH ROW
EXECUTE FUNCTION verifier_stock();

-- Test pour forcer l'erreur :
UPDATE produits SET stock = stock - 10 WHERE id = 1;
