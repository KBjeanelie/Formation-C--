Préparation

Installation de PostgreSQL

Windows

1. Téléchargez l'installateur officiel sur postgresql.org.

2. Lancez l'installation. Laissez les ports par défaut (5432).

3. Très important : Un mot de passe pour l'utilisateur superadmin postgres vous sera demandé. Notez-le, vous en aurez besoin !

Linux (Ubuntu / Debian)

Ouvrez votre terminal et tapez :

sudo apt update
sudo apt install postgresql postgresql-contrib

Par défaut, l'utilisateur s'appelle postgres sans mot de passe, mais lié au compte système. Pour se connecter :

sudo -u postgres psql

Pour définir un mot de passe (nécessaire pour se connecter depuis une interface graphique) :

\password postgres

macOS

La méthode la plus simple est d'utiliser Postgres.app :

1. Téléchargez-le sur postgresapp.com.

2. Glissez l'application dans votre dossier Applications et lancez-la.

Alternative via Homebrew :

brew install postgresql
brew services start postgresql

L'interface graphique (Client SQL)

Pour écrire vos requêtes et TPs de manière confortable, il vous faut un client. Deux excellents choix gratuits :

  • pgAdmin 4 : L'outil officiel, souvent installé avec PostgreSQL sous Windows.
  • DBeaver (Recommandé) : Client universel très léger et puissant. Téléchargeable sur dbeaver.io.

Pour vous connecter dans DBeaver, créez une nouvelle connexion PostgreSQL : Hôte : localhost, Port : 5432, Base : postgres, Utilisateur : postgres, et votre mot de passe.

Notions de base (Pour les habitués de MySQL)

PostgreSQL est plus strict et respectueux des standards SQL que MySQL. Voici quelques différences clés :

  • AUTO_INCREMENT devient SERIAL : En PostgreSQL, pour avoir un ID qui s'incrémente tout seul, on utilise le type SERIAL (ou BIGSERIAL) lors de la création de la table.
  • Base de données != Schéma : Dans MySQL, créer une base revient à créer un schéma. Dans PostgreSQL, une base de données peut contenir plusieurs schémas. Par défaut, vos tables sont créées dans le schéma nommé public.
  • Sensibilité à la casse : PostgreSQL met automatiquement tous les noms de tables et colonnes en minuscules. Si vous forcez des majuscules avec des guillemets (ex: CREATE TABLE "MaTable"), vous devrez TOUJOURS utiliser les guillemets dans vos requêtes. Il est recommandé de tout écrire en minuscules avec des underscores (ma_table).
  • Types stricts : PostgreSQL ne fera pas de conversion silencieuse et magique entre une chaîne "123" et un entier si cela peut poser problème. Il faut utiliser le cast (ex: '123'::INT).
  • Booléens : Utilisez les vrais booléens TRUE / FALSE au lieu de 1 / 0 (qui est le type TINYINT de MySQL).
