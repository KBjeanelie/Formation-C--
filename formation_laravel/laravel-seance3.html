01

Objectifs de la séance

  • Créer des composants Blade réutilisables pour éviter de dupliquer du HTML.
  • Construire des formulaires sécurisés (protection CSRF) et repeupler les champs après une erreur.
  • Valider les données envoyées par un formulaire, côté serveur.
  • Générer un contrôleur de ressource pour couvrir les 7 actions d'un CRUD en une seule ligne de routing.
02

Composants Blade

Un composant encapsule un morceau d'interface réutilisable — par exemple une carte, un bouton ou une alerte — pour ne pas répéter le même HTML dans dix vues différentes.
docker compose exec app php artisan make:component Alerte
<!-- resources/views/components/alerte.blade.php -->
<div class="alerte alerte-{{ $type }}">
    {{ $slot }}
</div>

Utilisation dans une autre vue :

<x-alerte type="success">
    Livre ajouté avec succès !
</x-alerte>
Ce qu'apporte $slot : le contenu placé entre <x-alerte> et </x-alerte> est injecté à la place de {{ $slot }} — le composant reste générique tout en acceptant un contenu différent à chaque utilisation.

03

Formulaires

<!-- resources/views/livres/create.blade.php -->
<form method="POST" action="/livres">
    @csrf

    <label>Titre</label>
    <input type="text" name="titre" value="{{ old('titre') }}">

    <label>Auteur</label>
    <input type="text" name="auteur" value="{{ old('auteur') }}">

    <button type="submit">Enregistrer</button>
</form>
Directive / helperRôle
@csrfAjoute un jeton anti-falsification de requête — obligatoire sur tout formulaire Laravel
old('champ')Réaffiche la valeur précédemment saisie si le formulaire est redisplayé après une erreur de validation
Piège fréquent : oublier @csrf provoque une erreur 419 Page Expired à la soumission — Laravel refuse par sécurité les requêtes POST sans jeton valide.
04

Validation

Validation directe dans le contrôleur, pour un cas simple :

public function store(Request $request)
{
    $donnees = $request->validate([
        'titre' => 'required|max:255',
        'auteur' => 'required|max:255',
    ]);

    Livre::create($donnees);

    return redirect('/livres');
}

Si la validation échoue, Laravel redirige automatiquement vers le formulaire précédent avec les erreurs, accessibles en vue avec @error :

<input type="text" name="titre" value="{{ old('titre') }}">
@error('titre')
    <p class="erreur">{{ $message }}</p>
@enderror

Pour des règles plus complexes ou réutilisées à plusieurs endroits, une Form Request dédiée :

docker compose exec app php artisan make:request StoreLivreRequest
// app/Http/Requests/StoreLivreRequest.php
public function rules(): array
{
    return [
        'titre' => 'required|max:255',
        'auteur' => 'required|max:255',
    ];
}

public function authorize(): bool
{
    return true;
}
// dans le contrôleur
public function store(StoreLivreRequest $request)
{
    Livre::create($request->validated());
    return redirect('/livres');
}
Pourquoi une Form Request plutôt que $request->validate() partout : dès que les mêmes règles doivent s'appliquer à la création et à la modification, ou qu'elles deviennent longues, centraliser dans une classe dédiée évite de dupliquer le tableau de règles dans chaque méthode du contrôleur.
05

CRUD complet avec un contrôleur de ressource

Un CRUD suit toujours le même schéma de 7 actions (liste, formulaire de création, enregistrement, détail, formulaire d'édition, mise à jour, suppression) — Laravel les génère d'un coup.
docker compose exec app php artisan make:controller LivreController --resource
// routes/web.php
Route::resource('livres', LivreController::class);
MéthodeVerbe + URLRôle
indexGET /livresListe
createGET /livres/createFormulaire de création
storePOST /livresEnregistrement
editGET /livres/{id}/editFormulaire de modification
updatePUT /livres/{id}Mise à jour
destroyDELETE /livres/{id}Suppression
// app/Http/Controllers/LivreController.php
public function index()
{
    return view('livres.index', ['livres' => Livre::all()]);
}

public function destroy(Livre $livre)
{
    $livre->delete();
    return redirect('/livres');
}
Livre $livre directement en paramètre : c'est le "route model binding" — Laravel va lui-même chercher le livre correspondant à l'identifiant dans l'URL, plutôt que d'écrire manuellement Livre::find($id) dans chaque méthode.

Ex. 2

Formulaire d'ajout de cours avec validation

intermédiaire

Créer une table et un modèle Cours (nom, credits), un formulaire de création avec @csrf, et une validation qui exige nom et un credits entier entre 1 et 10, avec affichage des erreurs via @error.

Voir la solution 
<!-- resources/views/cours/create.blade.php -->
<form method="POST" action="/cours">
    @csrf
    <input type="text" name="nom" value="{{ old('nom') }}">
    @error('nom')<p>{{ $message }}</p>@enderror

    <input type="number" name="credits" value="{{ old('credits') }}">
    @error('credits')<p>{{ $message }}</p>@enderror

    <button type="submit">Ajouter</button>
</form>
// app/Http/Controllers/CoursController.php
public function store(Request $request)
{
    $donnees = $request->validate([
        'nom' => 'required|max:255',
        'credits' => 'required|integer|min:1|max:10',
    ]);

    Cours::create($donnees);

    return redirect('/cours');
}
Ex. 3

Form Request dédiée

intermédiaire

Reprendre l'exercice 2 et déplacer les règles de validation dans une StoreCoursRequest, réutilisée à la fois pour store et pour update.

Voir la solution 
docker compose exec app php artisan make:request StoreCoursRequest
// app/Http/Requests/StoreCoursRequest.php
public function authorize(): bool { return true; }

public function rules(): array
{
    return [
        'nom' => 'required|max:255',
        'credits' => 'required|integer|min:1|max:10',
    ];
}
// app/Http/Controllers/CoursController.php
public function store(StoreCoursRequest $request)
{
    Cours::create($request->validated());
    return redirect('/cours');
}

public function update(StoreCoursRequest $request, Cours $cours)
{
    $cours->update($request->validated());
    return redirect('/cours');
}
Ex. 4

CRUD complet des cours

défi

Générer un CoursController en --resource, déclarer Route::resource('cours', CoursController::class), implémenter les 6 méthodes restantes (index, create, edit, update, destroy — store vient de l'exercice 3), avec des vues index.blade.php et edit.blade.php. Vérifier tout le cycle : créer un cours, le modifier, le supprimer, en le testant via docker compose exec app et le navigateur.

Voir la solution 
// routes/web.php
Route::resource('cours', CoursController::class);
// app/Http/Controllers/CoursController.php
public function index()
{
    return view('cours.index', ['cours' => Cours::all()]);
}

public function create()
{
    return view('cours.create');
}

public function edit(Cours $cours)
{
    return view('cours.edit', ['cours' => $cours]);
}

public function destroy(Cours $cours)
{
    $cours->delete();
    return redirect('/cours');
}
<!-- resources/views/cours/index.blade.php -->
@foreach ($cours as $c)
    <p>
        {{ $c->nom }} ({{ $c->credits }} crédits)
        <a href="/cours/{{ $c->id }}/edit">Modifier</a>
        <form method="POST" action="/cours/{{ $c->id }}" style="display:inline">
            @csrf @method('DELETE')
            <button type="submit">Supprimer</button>
        </form>
    </p>
@endforeach

@method('DELETE') est nécessaire car les formulaires HTML ne savent envoyer que du GET ou du POST — cette directive simule une requête DELETE que Laravel sait reconnaître, en complément du POST réel envoyé par le navigateur.
