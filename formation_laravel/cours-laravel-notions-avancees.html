Laravel : Notions Avancées

Approfondissez vos connaissances en Laravel avec les Jobs/Queues, les Events, l'Autorisation (Gates/Policies) et les API Resources.

01

Files d'attente (Queues) et Tâches (Jobs)

Dans une application web, certaines tâches prennent du temps (ex: envoyer un email, générer un PDF, redimensionner une image). Si on les exécute de manière synchrone, l'utilisateur doit attendre que la tâche se termine avant que la page ne se charge. Les Queues permettent de différer ces tâches en arrière-plan.

Création d'un Job

Pour générer un Job, on utilise Artisan :

php artisan make:job ProcessPodcast

Cela crée une classe dans app/Jobs. La logique s'écrit dans la méthode handle().

<?php
namespace App\Jobs;

use App\Models\Podcast;
use Illuminate\Bus\Queueable;
use Illuminate\Contracts\Queue\ShouldQueue;
use Illuminate\Foundation\Bus\Dispatchable;
use Illuminate\Queue\InteractsWithQueue;
use Illuminate\Queue\SerializesModels;

class ProcessPodcast implements ShouldQueue
{
    use Dispatchable, InteractsWithQueue, Queueable, SerializesModels;

    public $podcast;

    public function __construct(Podcast $podcast) {
        $this->podcast = $podcast;
    }

    public function handle() {
        // Logique de traitement long (ex: encodage audio)
    }
}
TP Pratique : Envoi d'email différé

Objectif : Créez un Job nommé SendWelcomeEmail qui simule l'envoi d'un email (par exemple en utilisant Log::info) à un utilisateur lors de son inscription, puis dispatchez-le depuis un contrôleur.

Voir la solution

1. Créez le Job :

php artisan make:job SendWelcomeEmail

2. Modifiez le Job généré :

<?php
namespace App\Jobs;

use App\Models\User;
use Illuminate\Bus\Queueable;
use Illuminate\Contracts\Queue\ShouldQueue;
use Illuminate\Foundation\Bus\Dispatchable;
use Illuminate\Queue\InteractsWithQueue;
use Illuminate\Queue\SerializesModels;
use Illuminate\Support\Facades\Log;

class SendWelcomeEmail implements ShouldQueue
{
    use Dispatchable, InteractsWithQueue, Queueable, SerializesModels;

    protected $user;

    public function __construct(User $user) {
        $this->user = $user;
    }

    public function handle() {
        Log::info("Envoi de l'email de bienvenue à : " . $this->user->email);
        // sleep(3); // Simulation de délai
    }
}

3. Dispatchez le Job dans votre Contrôleur :

use App\Jobs\SendWelcomeEmail;

public function register(Request $request) {
    // Création de l'utilisateur...
    $user = User::create($request->all());

    // Dispatch du Job
    SendWelcomeEmail::dispatch($user);

    return response()->json(['message' => 'Inscription réussie']);
}
02

Autorisation : Gates et Policies

Laravel sépare l'authentification (qui es-tu ?) de l'autorisation (as-tu le droit de faire ça ?). Les Gates sont des fermetures (closures) simples, souvent utilisées pour des actions globales. Les Policies sont des classes liées à un modèle spécifique (ex: PostPolicy pour le modèle Post).

Création d'une Policy

php artisan make:policy PostPolicy --model=Post

Dans la policy, on définit des méthodes qui retournent true ou false.

<?php
namespace App\Policies;

use App\Models\Post;
use App\Models\User;

class PostPolicy
{
    // L'utilisateur peut-il modifier ce post ?
    public function update(User $user, Post $post)
    {
        return $user->id === $post->user_id;
    }
}
TP Pratique : Protection de modification d'Article

Objectif : Dans un contrôleur ArticleController, empêchez un utilisateur de supprimer un article qui ne lui appartient pas en utilisant une Policy.

Voir la solution

1. Créez la Policy :

php artisan make:policy ArticlePolicy --model=Article

2. Définissez la méthode delete :

public function delete(User $user, Article $article) {
    return $user->id === $article->author_id;
}

3. Dans l'ArticleController :

public function destroy(Article $article) {
    // La méthode authorize renverra une erreur 403 si l'action n'est pas permise
    $this->authorize('delete', $article);
    
    $article->delete();
    return redirect('/articles');
}

Note : Dans Laravel 11+, l'autorisation peut aussi s'écrire : Gate::authorize('delete', $article);

03

Ressources API (Eloquent Resources)

Quand vous créez une API, vous ne voulez pas toujours renvoyer l'intégralité des colonnes de la base de données (ex: mots de passe hachés, dates de création). Les Ressources API agissent comme une couche de transformation entre vos modèles Eloquent et la réponse JSON renvoyée à l'utilisateur.

Création d'une Resource

php artisan make:resource UserResource

Dans app/Http/Resources/UserResource.php :

<?php
namespace App\Http\Resources;

use Illuminate\Http\Resources\Json\JsonResource;

class UserResource extends JsonResource
{
    public function toArray($request)
    {
        return [
            'id' => $this->id,
            'nom_complet' => $this->first_name . ' ' . $this->last_name,
            'email' => $this->email,
            'rejoint_le' => $this->created_at->format('Y-m-d'),
        ];
    }
}
TP Pratique : Formatage JSON d'un Produit

Objectif : Créez une ProductResource pour un modèle Product. Ne renvoyez que le nom, le prix_ttc (en multipliant le prix HT par 1.2), et cachez l'ID.

Voir la solution

1. Génération :

php artisan make:resource ProductResource

2. Modification de la méthode toArray :

public function toArray($request)
{
    return [
        'nom' => $this->name,
        'prix_ttc' => round($this->price_ht * 1.2, 2) . ' €',
        // On omet volontairement 'id' et 'created_at'
    ];
}

3. Utilisation dans le contrôleur :

public function show(Product $product) {
    return new ProductResource($product);
}

// Pour une liste (collection) de produits :
public function index() {
    return ProductResource::collection(Product::all());
}
