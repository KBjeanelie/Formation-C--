01

Objectifs de la séance

  • Créer et faire évoluer un schéma de base de données avec les migrations Laravel.
  • Créer des modèles Eloquent et comprendre le lien table ↔ classe PHP.
  • Effectuer des opérations CRUD (Create, Read, Update, Delete) avec Eloquent, sans écrire de SQL brut.
  • Définir des relations hasMany / belongsTo et belongsToMany entre modèles.
  • Peupler la base avec des seeders pour disposer de données de test.
02

Reprendre l'environnement Docker de la séance 1

Le docker-compose.yml de la séance 1 suffit ; toutes les commandes Artisan de cette séance s'exécutent à l'intérieur du conteneur app.
docker compose up -d
docker compose exec app php artisan migrate
Pourquoi exécuter les commandes via docker compose exec : PHP et Artisan vivent à l'intérieur du conteneur app, pas sur la machine hôte — exec lance la commande dans ce conteneur déjà démarré, exactement comme si on avait ouvert un terminal dedans.

Pour visualiser la base de données plus confortablement pendant les TP, on peut ajouter phpMyAdmin au docker-compose.yml :

phpmyadmin:
  image: phpmyadmin
  environment:
    PMA_HOST: db
  ports:
    - "8080:80"

Accessible ensuite sur http://localhost:8080.

03

Les migrations

Une migration décrit le schéma d'une table en PHP plutôt qu'en SQL brut — versionné avec le code, partagé par toute l'équipe, et rejouable sur n'importe quelle machine.
docker compose exec app php artisan make:migration create_etudiants_table
// database/migrations/..._create_etudiants_table.php
public function up(): void
{
    Schema::create('etudiants', function (Blueprint $table) {
        $table->id();
        $table->string('nom');
        $table->string('email')->unique();
        $table->integer('annee')->default(3);
        $table->timestamps();
    });
}
docker compose exec app php artisan migrate
MéthodeRôle
id()Clé primaire auto-incrémentée
string() / integer() / boolean()Types de colonnes
unique()Contrainte d'unicité
timestamps()Ajoute created_at et updated_at, gérés automatiquement
Piège fréquent : modifier directement une migration déjà exécutée en production n'a aucun effet — il faut créer une nouvelle migration (par exemple avec php artisan make:migration add_telephone_to_etudiants_table) pour faire évoluer une table existante.
04

Les modèles Eloquent

docker compose exec app php artisan make:model Etudiant
// app/Models/Etudiant.php
class Etudiant extends Model
{
    protected $fillable = ['nom', 'email', 'annee'];
}
À quoi sert $fillable : Eloquent refuse par sécurité de remplir en masse un champ non listé ici, pour éviter qu'un formulaire malveillant n'écrive dans une colonne sensible (comme un rôle "admin") non prévue pour être modifiée depuis l'extérieur.

Par convention, le modèle Etudiant correspond automatiquement à la table etudiants (nom au pluriel) — pas besoin de le préciser sauf cas particulier.

05

Requêtes CRUD avec Eloquent

// Create
Etudiant::create(['nom' => 'Fabrice', 'email' => 'fabrice@ecole.cg', 'annee' => 3]);

// Read
$tous = Etudiant::all();
$un = Etudiant::find(1);
$filtres = Etudiant::where('annee', 3)->get();

// Update
$etudiant = Etudiant::find(1);
$etudiant->annee = 4;
$etudiant->save();

// Delete
Etudiant::destroy(1);
Pourquoi Eloquent plutôt que du SQL brut : les requêtes ci-dessus fonctionnent à l'identique quelle que soit la base de données (MySQL, PostgreSQL, SQLite), et protègent automatiquement contre les injections SQL — écrire "WHERE annee = " . $valeur à la main serait risqué si $valeur vient d'un utilisateur.
06

Les relations entre modèles

Un-à-plusieurs (hasMany / belongsTo)

Un étudiant a plusieurs notes ; chaque note appartient à un étudiant :

// app/Models/Etudiant.php
public function notes()
{
    return $this->hasMany(Note::class);
}

// app/Models/Note.php
public function etudiant()
{
    return $this->belongsTo(Etudiant::class);
}
$etudiant = Etudiant::find(1);
foreach ($etudiant->notes as $note) {
    echo $note->valeur;
}

La migration correspondante pour notes doit contenir une clé étrangère :

$table->foreignId('etudiant_id')->constrained();

Plusieurs-à-plusieurs (belongsToMany)

Un étudiant est inscrit à plusieurs cours ; un cours a plusieurs étudiants — nécessite une table pivot cours_etudiant :

// app/Models/Etudiant.php
public function cours()
{
    return $this->belongsToMany(Cours::class);
}
Pourquoi une table pivot : une relation plusieurs-à-plusieurs ne peut pas être stockée par une simple clé étrangère dans l'une ou l'autre table — il faut une troisième table qui associe chaque paire (étudiant, cours) possible.

Ex. 3

Relation Étudiant / Notes

intermédiaire

Créer les tables et modèles Etudiant et Note (valeur, matiere, etudiant_id), déclarer la relation hasMany/belongsTo, puis écrire une route qui affiche, pour un étudiant donné, la liste de ses notes et leur moyenne.

Voir la solution 
// database/migrations/..._create_notes_table.php
Schema::create('notes', function (Blueprint $table) {
    $table->id();
    $table->foreignId('etudiant_id')->constrained();
    $table->string('matiere');
    $table->decimal('valeur', 4, 2);
    $table->timestamps();
});
// app/Models/Etudiant.php
public function notes()
{
    return $this->hasMany(Note::class);
}

// app/Models/Note.php
protected $fillable = ['etudiant_id', 'matiere', 'valeur'];

public function etudiant()
{
    return $this->belongsTo(Etudiant::class);
}
// routes/web.php
Route::get('/etudiants/{id}/notes', function ($id) {
    $etudiant = Etudiant::find($id);
    $moyenne = $etudiant->notes->avg('valeur');

    return response()->json([
        'notes' => $etudiant->notes,
        'moyenne' => $moyenne,
    ]);
});

$etudiant->notes déclenche automatiquement la relation définie dans le modèle et retourne une collection, sur laquelle des méthodes comme avg() peuvent directement s'appliquer.

Ex. 4

Inscriptions étudiants / cours (plusieurs-à-plusieurs)

défi

Créer les tables cours et une table pivot cours_etudiant (etudiant_id, cours_id), déclarer belongsToMany dans les deux sens, inscrire un étudiant à deux cours avec attach(), puis afficher la liste des cours d'un étudiant.

Voir la solution 
// database/migrations/..._create_cours_table.php
Schema::create('cours', function (Blueprint $table) {
    $table->id();
    $table->string('nom');
    $table->timestamps();
});

// database/migrations/..._create_cours_etudiant_table.php
Schema::create('cours_etudiant', function (Blueprint $table) {
    $table->id();
    $table->foreignId('etudiant_id')->constrained();
    $table->foreignId('cours_id')->constrained();
    $table->timestamps();
});
// app/Models/Etudiant.php
public function cours()
{
    return $this->belongsToMany(Cours::class);
}

// app/Models/Cours.php
public function etudiants()
{
    return $this->belongsToMany(Etudiant::class);
}
// routes/web.php — inscrire, à exécuter une seule fois
Route::get('/test-inscription', function () {
    $etudiant = Etudiant::find(1);
    $etudiant->cours()->attach([1, 2]);
    return 'Inscrit';
});

Route::get('/etudiants/{id}/cours', function ($id) {
    return response()->json(Etudiant::find($id)->cours);
});

Laravel devine automatiquement le nom de la table pivot (cours_etudiant, les deux noms de modèles au singulier dans l'ordre alphabétique) — c'est pourquoi elle n'a pas besoin d'être précisée dans belongsToMany() ici.
