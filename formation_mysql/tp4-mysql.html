Séance 4 — 4 heures

Bascule vers le NoSQL (MongoDB)

Oubliez les tables, les colonnes rigides et les jointures SQL complexes. Découvrez le monde du stockage Documentaire JSON avec MongoDB.

1. Le paradigme NoSQL (Not Only SQL)

Le NoSQL a été créé pour répondre aux problèmes d'évolution (scalabilité horizontale) des géants du web. Plutôt que d'avoir un gros serveur très cher, on répartit la donnée sur des dizaines de petits serveurs.

Le modèle Documentaire

Contrairement à PostgreSQL où une donnée est découpée dans plusieurs tables (Client, Commande, Produit), dans MongoDB (Document-Oriented), on va tout regrouper dans un objet JSON (BSON en interne).

  • Une Table SQL s'appelle une Collection.
  • Une Ligne (Row) SQL s'appelle un Document.
  • Il n'y a pas de schéma fixe : deux documents d'une même collection peuvent avoir des champs différents.
L'avantage de l'imbrication : Si un article a des tags et des commentaires, en SQL il faudrait 3 tables et faire 2 JOIN. Dans MongoDB, les tags sont un simple tableau ["NoSQL", "Tuto"], et les commentaires sont des sous-documents inclus directement dans l'article. Une seule lecture disque suffit !

Syntaxe de base (CRUD)

-- SQL
INSERT INTO users (nom, age) VALUES ('Alice', 25);
SELECT * FROM users WHERE age > 20;
UPDATE users SET age = 26 WHERE nom = 'Alice';

-- MongoDB (JavaScript Shell)
db.users.insertOne({ nom: 'Alice', age: 25 });
db.users.find({ age: { $gt: 20 } });
db.users.updateOne({ nom: 'Alice' }, { $set: { age: 26 } });

2. Préparation du Shell (mongosh)

Ouvrez votre terminal et tapez mongosh (ou utilisez l'onglet mongosh de MongoDB Compass).

Sélectionnez la base de données (elle sera créée automatiquement dès qu'on y insérera quelque chose) :

use blog_db

3. Travaux Pratiques (10 exercices)

TP 01

Insert One : Créer un Document complexe

Créez un document dans la collection articles contenant un titre, un auteur, un tableau de tags (string) et un tableau de commentaires (objets avec utilisateur et texte).

▶ Voir la solution 
db.articles.insertOne({
    titre: "Découvrir MongoDB",
    auteur: "Walter",
    tags: ["NoSQL", "Base de données", "JSON"],
    commentaires: [
        { user: "Alice", texte: "Super introduction !", date: new Date() },
        { user: "Bob", texte: "Très clair, merci.", date: new Date() }
    ],
    vues: 120
});

-- Afficher le résultat :
db.articles.find().pretty();
TP 02

Insert Many : Insérer plusieurs données

Insérez au moins 3 nouveaux articles en une seule requête avec insertMany. Variez les auteurs et le nombre de vues.

▶ Voir la solution 
db.articles.insertMany([
    {
        titre: "PostgreSQL vs MongoDB",
        auteur: "Clara",
        tags: ["SQL", "NoSQL", "Comparatif"],
        vues: 450
    },
    {
        titre: "Le Pipeline d'Agrégation",
        auteur: "Walter",
        tags: ["MongoDB", "Avancé"],
        vues: 80
    },
    {
        titre: "Tutoriel ExpressJS",
        auteur: "Alice",
        tags: ["JS", "Web"],
        vues: 15
    }
]);
TP 03

Find : Recherche exacte et imbriquée

Trouvez tous les articles écrits par "Walter" qui ont le tag "NoSQL".

▶ Voir la solution 
-- Le ET (AND) est implicite quand on sépare les champs par une virgule.
-- MongoDB cherche automatiquement dans les tableaux si on passe une valeur simple.

db.articles.find({
    auteur: "Walter",
    tags: "NoSQL"
});
TP 04

Les Opérateurs (Greater Than)

Trouvez les articles qui ont strictement plus de 100 vues. Utilisez l'opérateur $gt (greater than).

▶ Voir la solution 
db.articles.find({
    vues: { $gt: 100 }
});

-- Note : Pour "supérieur ou égal", utilisez $gte. 
-- Pour "inférieur", c'est $lt et $lte.
TP 05

Update : Modifier un champ

Mettez à jour le titre de l'article écrit par "Clara" pour qu'il devienne "SQL vs NoSQL : Le guide définitif". (Utilisez l'opérateur $set).

▶ Voir la solution 
-- updateOne prend 2 paramètres : { condition }, { modification }

db.articles.updateOne(
    { auteur: "Clara" },
    { $set: { titre: "SQL vs NoSQL : Le guide définitif" } }
);

-- Si on oublie le $set et qu'on fait juste { titre: "..." }, 
-- MongoDB remplace TOUT le document par ce seul champ ! (Attention)
TP 06

Update : Incrémenter (Maths)

L'article de Clara vient d'être lu. Ajoutez 1 au compteur de vues sans utiliser $set (pour éviter les problèmes de concurrence). Utilisez l'opérateur mathématique $inc.

▶ Voir la solution 
db.articles.updateOne(
    { auteur: "Clara" },
    { $inc: { vues: 1 } }
);

-- Pratique : pas besoin de faire un SELECT avant pour connaître la valeur, 
-- le moteur incrémente de manière atomique.
TP 07

Update : Pousser dans un tableau

Ajoutez le tag "Performance" à l'article de Clara (qui est un tableau). Utilisez l'opérateur $push.

▶ Voir la solution 
db.articles.updateOne(
    { auteur: "Clara" },
    { $push: { tags: "Performance" } }
);

-- Si vous vouliez ajouter un commentaire :
-- { $push: { commentaires: { user: "David", texte: "Intéressant" } } }
TP 08

Suppression de Document

Supprimez l'article dont le titre est "Tutoriel ExpressJS" avec deleteOne.

▶ Voir la solution 
db.articles.deleteOne({
    titre: "Tutoriel ExpressJS"
});
TP 09

L'Agrégation : Regrouper et Calculer (L'équivalent du GROUP BY)

On rentre dans le dur ! Utilisez aggregate pour calculer le total des vues pour CHAQUE auteur. (Utilisez le stage $group).

▶ Voir la solution 
-- Le pipeline d'agrégation est un tableau d'étapes (stages)

db.articles.aggregate([
    {
        $group: {
            _id: "$auteur",                 -- On groupe par la clé auteur (notez le $ avant le nom)
            total_vues: { $sum: "$vues" },  -- On fait la somme de la clé vues
            nb_articles: { $sum: 1 }        -- On compte +1 pour chaque document trouvé
        }
    }
]);
TP 10

Indexation MongoDB

Tout comme PostgreSQL, MongoDB a besoin d'index pour les grandes collections. Créez un index B-Tree sur le champ auteur.

▶ Voir la solution 
-- Créer l'index croissant (1) ou décroissant (-1)
db.articles.createIndex({ auteur: 1 });

-- Afficher tous les index de la collection
db.articles.getIndexes();

-- On peut aussi analyser une requête avec explain :
db.articles.find({ auteur: "Walter" }).explain("executionStats");
