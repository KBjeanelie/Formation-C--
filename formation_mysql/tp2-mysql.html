Transactions & Sécurité MySQL

Garantissez l'intégrité des données avec START TRANSACTION et protégez votre base avec le système de rôles de MySQL 8.

1. Les Transactions MySQL

MySQL supporte les transactions via le moteur InnoDB. Le moteur MyISAM (ancien) n'en supporte pas — c'est une raison de plus d'utiliser InnoDB.

START TRANSACTION;  -- Démarre la transaction (aussi écrit BEGIN)

  UPDATE comptes SET solde = solde - 200 WHERE id = 1;
  UPDATE comptes SET solde = solde + 200 WHERE id = 2;

COMMIT;    -- Valide toutes les modifications
-- ou
ROLLBACK;  -- Annule tout depuis le START TRANSACTION

Les SAVEPOINT

START TRANSACTION;
  UPDATE comptes SET solde = solde - 50 WHERE id = 1;
  SAVEPOINT etape1;

  UPDATE comptes SET solde = solde - 100 WHERE id = 1;
  -- On se ravise :
  ROLLBACK TO SAVEPOINT etape1;  -- Annule seulement depuis etape1

COMMIT;  -- Seul le premier retrait de 50€ est validé
Autocommit : Par défaut, MySQL est en mode autocommit = 1 ce qui signifie que chaque requête est une transaction automatiquement committée. Dès que vous tapez START TRANSACTION, ce mode est suspendu jusqu'au prochain COMMIT ou ROLLBACK.

Gestion des erreurs avec les gestionnaires (DECLARE HANDLER)

DELIMITER //
CREATE PROCEDURE virement_securise(...)
BEGIN
    DECLARE EXIT HANDLER FOR SQLEXCEPTION
    BEGIN
        ROLLBACK;  -- En cas d'erreur SQL, on annule tout
        SELECT 'Erreur : transaction annulée.' AS message;
    END;

    START TRANSACTION;
        -- ... opérations ...
    COMMIT;
END //
DELIMITER ;

2. Sécurité : Rôles et Utilisateurs (MySQL 8+)

MySQL a introduit les rôles dans la version 8. La syntaxe diffère légèrement de PostgreSQL.

-- Créer un utilisateur
CREATE USER 'dev'@'localhost' IDENTIFIED BY 'SecretPwd!1';

-- Créer un rôle de groupe
CREATE ROLE 'lecteurs', 'editeurs';

-- Assigner des droits au rôle
GRANT SELECT ON banking.* TO 'lecteurs';
GRANT SELECT, INSERT, UPDATE ON banking.* TO 'editeurs';

-- Assigner le rôle à l'utilisateur
GRANT 'lecteurs' TO 'dev'@'localhost';

-- Activer les rôles par défaut (sinon l'utilisateur doit faire SET ROLE)
SET DEFAULT ROLE 'lecteurs' TO 'dev'@'localhost';

-- Afficher les droits d'un utilisateur
SHOW GRANTS FOR 'dev'@'localhost';

3. Base de travail — Système Bancaire

CREATE DATABASE IF NOT EXISTS banking CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE banking;

DROP TABLE IF EXISTS virements, journal_erreurs, comptes;

CREATE TABLE comptes (
    id INT AUTO_INCREMENT PRIMARY KEY,
    titulaire VARCHAR(100) NOT NULL,
    solde DECIMAL(12,2) DEFAULT 0 CHECK (solde >= 0),
    type_compte VARCHAR(20) DEFAULT 'courant'
) ENGINE=InnoDB;

CREATE TABLE virements (
    id INT AUTO_INCREMENT PRIMARY KEY,
    compte_source INT, compte_dest INT,
    montant DECIMAL(12,2),
    statut VARCHAR(20) DEFAULT 'en_attente',
    effectue_le TIMESTAMP DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB;

CREATE TABLE journal_erreurs (
    id INT AUTO_INCREMENT PRIMARY KEY,
    message TEXT,
    contexte TEXT,
    survenu_le TIMESTAMP DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB;

4. Travaux Pratiques (10 exercices)

TP 01

Transaction simple : Virement manuel

Effectuez un virement de 200€ du compte d'Alice (id=1) vers Bob (id=2) dans un bloc transactionnel. Vérifiez les soldes avant et après.

▶ Voir la solution 
SELECT id, titulaire, solde FROM comptes WHERE id IN (1,2);

START TRANSACTION;
  UPDATE comptes SET solde = solde - 200 WHERE id = 1;
  UPDATE comptes SET solde = solde + 200 WHERE id = 2;
COMMIT;

SELECT id, titulaire, solde FROM comptes WHERE id IN (1,2);
TP 02

ROLLBACK : Simuler un crash

Ouvrez une transaction, débitez 100€ d'Alice, puis annulez-la. Vérifiez que son solde est inchangé.

▶ Voir la solution 
SELECT solde FROM comptes WHERE id = 1;

START TRANSACTION;
  UPDATE comptes SET solde = solde - 100 WHERE id = 1;
  SELECT solde FROM comptes WHERE id = 1; -- visible dans cette session
ROLLBACK;

SELECT solde FROM comptes WHERE id = 1; -- solde restauré
TP 03

Procédure : Virement sécurisé avec HANDLER

Créez une procédure effectuer_virement(source, dest, montant) avec un DECLARE EXIT HANDLER FOR SQLEXCEPTION qui fait un ROLLBACK automatique en cas d'erreur.

▶ Voir la solution 
DELIMITER //
CREATE PROCEDURE effectuer_virement(IN p_src INT, IN p_dst INT, IN p_mnt DECIMAL(12,2))
BEGIN
    DECLARE v_solde DECIMAL(12,2);
    DECLARE EXIT HANDLER FOR SQLEXCEPTION
    BEGIN
        ROLLBACK;
        INSERT INTO journal_erreurs(message) VALUES ('Virement échoué - transaction annulée');
        SELECT 'ERREUR: virement annulé' AS statut;
    END;

    START TRANSACTION;
        IF p_mnt <= 0 THEN SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT='Montant invalide'; END IF;
        SELECT solde INTO v_solde FROM comptes WHERE id = p_src FOR UPDATE;
        IF v_solde < p_mnt THEN SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT='Fonds insuffisants'; END IF;
        UPDATE comptes SET solde = solde - p_mnt WHERE id = p_src;
        UPDATE comptes SET solde = solde + p_mnt WHERE id = p_dst;
        INSERT INTO virements(compte_source, compte_dest, montant, statut) VALUES(p_src, p_dst, p_mnt, 'effectue');
    COMMIT;
    SELECT CONCAT('Virement de ', p_mnt, '€ OK') AS statut;
END //
DELIMITER ;

CALL effectuer_virement(1, 2, 50);
CALL effectuer_virement(5, 1, 100); -- Doit échouer
SELECT * FROM virements;
TP 04

SAVEPOINT : Transaction multi-étapes

Effectuez 3 virements dans une même transaction. Si le 3ème échoue (fonds insuffisants), revenez au savepoint après le 2ème sans annuler les deux premiers.

▶ Voir la solution 
START TRANSACTION;
  UPDATE comptes SET solde = solde - 30 WHERE id = 1;
  UPDATE comptes SET solde = solde + 30 WHERE id = 2;
  SAVEPOINT apres_premier;

  UPDATE comptes SET solde = solde - 100 WHERE id = 3;
  UPDATE comptes SET solde = solde + 100 WHERE id = 1;
  SAVEPOINT apres_deuxieme;

  -- Virement qui va échouer (David n'a pas de solde) :
  UPDATE comptes SET solde = solde - 500 WHERE id = 5;
  -- La contrainte CHECK solde >= 0 va déclencher une erreur.
  -- En MySQL, l'erreur ne rollback pas automatiquement. On doit le faire manuellement :
  ROLLBACK TO SAVEPOINT apres_deuxieme;
COMMIT;

SELECT id, titulaire, solde FROM comptes ORDER BY id;
TP 05

Créer un rôle en lecture seule

Créez un rôle conseiller avec seulement le droit SELECT sur les tables comptes et virements. Assignez-le à un utilisateur martin.

▶ Voir la solution 
CREATE ROLE 'conseiller';
GRANT SELECT ON banking.comptes TO 'conseiller';
GRANT SELECT ON banking.virements TO 'conseiller';

CREATE USER 'martin'@'%' IDENTIFIED BY 'martin_pass!';
GRANT 'conseiller' TO 'martin'@'%';
SET DEFAULT ROLE 'conseiller' TO 'martin'@'%';

SHOW GRANTS FOR 'martin'@'%';
TP 06

Rôle applicatif sur procédure uniquement

Créez un utilisateur app qui peut seulement exécuter la procédure effectuer_virement, sans accès direct aux tables.

▶ Voir la solution 
CREATE USER 'app'@'%' IDENTIFIED BY 'app_secret!';

-- Donner uniquement le droit d'exécuter la procédure
GRANT EXECUTE ON PROCEDURE banking.effectuer_virement TO 'app'@'%';

-- Ne pas donner de droits sur les tables
-- L'astuce est que la procédure est créée avec SQL SECURITY DEFINER (par défaut)
-- Elle s'exécutera avec les droits du créateur (root), pas de 'app'.
TP 07

Trigger : Bloquer les virements suspects

Créez un trigger BEFORE INSERT sur virements qui bloque tout virement supérieur à 10 000€.

▶ Voir la solution 
DELIMITER //
CREATE TRIGGER trg_virement_suspect
BEFORE INSERT ON virements
FOR EACH ROW
BEGIN
    IF NEW.montant > 10000 THEN
        INSERT INTO journal_erreurs(message, contexte)
        VALUES('Virement bloqué', CONCAT('Montant: ', NEW.montant, '€'));
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = 'Virement refusé : dépasse le plafond de 10 000€.';
    END IF;
END //
DELIMITER ;

INSERT INTO virements(compte_source, compte_dest, montant) VALUES (4, 1, 15000);
TP 08

Observation de l'isolation (2 sessions)

Dans une session A, démarrez une transaction et modifiez un solde sans committer. Dans une session B, lisez le même solde. Observez que B ne voit pas la modification non-commitée (READ COMMITTED).

▶ Voir la solution 
-- === SESSION A ===
START TRANSACTION;
UPDATE comptes SET solde = 99999 WHERE id = 1;
-- NE PAS COMMITTER

-- === SESSION B ===
SELECT solde FROM comptes WHERE id = 1;
-- Résultat : 1300€ (MySQL est en READ COMMITTED par défaut, la session B ne voit rien)

-- === SESSION A ===
COMMIT;

-- === SESSION B ===
SELECT solde FROM comptes WHERE id = 1;
-- Résultat : 99999€ (maintenant visible)
UPDATE comptes SET solde = 1300 WHERE id = 1; -- Remise en état
TP 09

Vue sécurisée (VIEW) pour masquer les données sensibles

Créez une vue v_comptes_public qui expose le titulaire et le type de compte, mais masque le solde exact avec un texte générique selon le niveau (> 1000€ : "Solide", < 1000€ : "Faible").

▶ Voir la solution 
CREATE VIEW v_comptes_public AS
SELECT
    id,
    titulaire,
    type_compte,
    CASE
        WHEN solde > 1000 THEN 'Solide'
        WHEN solde > 0 THEN 'Faible'
        ELSE 'Insuffisant'
    END AS niveau_solde
FROM comptes;

-- Donner l'accès à la vue (pas à la table) :
GRANT SELECT ON banking.v_comptes_public TO 'conseiller';

SELECT * FROM v_comptes_public;
TP 10

Procédure de clôture mensuelle

Créez une procédure cloture_mensuelle() dans une transaction unique : applique 2% d'intérêts aux comptes épargne, prélève 5€ de frais sur les comptes courants, et enregistre un rapport dans journal_erreurs.

▶ Voir la solution 
DELIMITER //
CREATE PROCEDURE cloture_mensuelle()
BEGIN
    DECLARE nb_epargne INT DEFAULT 0;
    DECLARE nb_courant INT DEFAULT 0;

    DECLARE EXIT HANDLER FOR SQLEXCEPTION BEGIN ROLLBACK; END;

    START TRANSACTION;
        UPDATE comptes SET solde = ROUND(solde * 1.02, 2) WHERE type_compte = 'epargne';
        SET nb_epargne = ROW_COUNT();

        UPDATE comptes SET solde = solde - 5 WHERE type_compte = 'courant' AND solde > 0;
        SET nb_courant = ROW_COUNT();

        INSERT INTO journal_erreurs(message, contexte)
        VALUES('CLOTURE MENSUELLE OK', CONCAT(nb_epargne, ' épargne traités, ', nb_courant, ' courants traités'));
    COMMIT;

    SELECT CONCAT('Clôture OK: ', nb_epargne, ' épargne, ', nb_courant, ' courants') AS bilan;
END //
DELIMITER ;

CALL cloture_mensuelle();
SELECT id, titulaire, solde, type_compte FROM comptes ORDER BY type_compte;
