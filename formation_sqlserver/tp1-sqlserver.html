T-SQL : Procédures Stockées & Triggers

Maîtrisez la programmation serveur en T-SQL. Le langage procédural de SQL Server est proche du C# et très puissant pour la logique métier.

1. Structure d'une Procédure Stockée T-SQL

Contrairement à PostgreSQL (PL/pgSQL avec $$) et MySQL (DELIMITER), T-SQL n'a pas de délimiteur spécial. La procédure est un objet autonome délimité par CREATE PROCEDURE ... AS BEGIN ... END.

CREATE OR ALTER PROCEDURE nom_procedure   -- CREATE OR ALTER remplace CREATE + DROP si existe
    @param1 INT,                -- Paramètres préfixés par @
    @param2 NVARCHAR(100) OUTPUT  -- Paramètre de sortie
AS
BEGIN
    SET NOCOUNT ON;  -- Bonne pratique : ne pas renvoyer les "X lignes affectées"
    DECLARE @ma_variable INT = 0;  -- Déclaration des variables locales

    IF @param1 > 10
        SET @param2 = N'Grand';
    ELSE
        SET @param2 = N'Petit';
END;
GO

Les Triggers T-SQL : Statement-Level avec tables virtuelles

C'est la grande différence avec PostgreSQL et MySQL. En SQL Server, les triggers s'exécutent une fois par opération (pas par ligne). Deux tables virtuelles sont disponibles :

  • inserted — Table contenant toutes les nouvelles lignes (INSERT / UPDATE).
  • deleted — Table contenant toutes les anciennes lignes (UPDATE / DELETE).
Exemple : Si un UPDATE affecte 100 lignes, le trigger s'exécute une seule fois, mais inserted et deleted contiennent chacune 100 lignes. Il faut toujours faire un JOIN avec ces tables, jamais supposer qu'elles n'ont qu'une ligne. 
CREATE OR ALTER TRIGGER trg_exemple
ON ma_table
AFTER INSERT
AS
BEGIN
    SET NOCOUNT ON;
    -- "inserted" contient TOUTES les lignes insérées par l'opération
    SELECT id, nom FROM inserted;
END;
GO

    id INT IDENTITY(1,1) PRIMARY KEY,
    nom NVARCHAR(100) NOT NULL,

CREATE TABLE produits (
    id INT IDENTITY(1,1) PRIMARY KEY,
    nom NVARCHAR(100) NOT NULL,
    prix DECIMAL(10,2) CHECK (prix >= 0),

    id INT IDENTITY(1,1) PRIMARY KEY,
    client_id INT FOREIGN KEY REFERENCES clients(id) ON DELETE CASCADE,

    quantite INT CHECK (quantite > 0),
    prix_total DECIMAL(10,2),
    date_cmd DATETIME2 DEFAULT GETDATE()
);

3. Travaux Pratiques (10 exercices)

TP 01

Fonction scalaire : Calcul de la remise

Créez une fonction scalaire dbo.get_remise(@client_id INT) qui retourne un taux de remise DECIMAL(4,2).

▶ Voir la solution 
CREATE OR ALTER FUNCTION dbo.get_remise(@client_id INT)
RETURNS DECIMAL(4,2)
AS
BEGIN
    DECLARE @pts INT;
    SELECT @pts = points_fidelite FROM clients WHERE id = @client_id;
    IF @pts IS NULL RETURN 0.00;
    IF @pts >= 500 RETURN 0.20;
    IF @pts >= 100 RETURN 0.10;
    RETURN 0.00;
END;
GO

-- Test :
SELECT nom, points_fidelite, dbo.get_remise(id)*100 AS remise_pct FROM clients;
TP 02

Fonction scalaire : Prix final

Créez dbo.prix_final(@client INT, @produit INT) qui appelle get_remise et retourne le prix après réduction.

▶ Voir la solution 
CREATE OR ALTER FUNCTION dbo.prix_final(@client INT, @produit INT)
RETURNS DECIMAL(10,2)
AS
BEGIN
    DECLARE @prix DECIMAL(10,2);
    SELECT @prix = prix FROM produits WHERE id = @produit;
    RETURN ROUND(@prix * (1 - dbo.get_remise(@client)), 2);
END;
GO

SELECT dbo.prix_final(3, 1); -- Clara (500pts) Laptop (1200€) → 960€
TP 03

Procédure : Passer une commande

Créez passer_commande @client, @produit, @qte avec gestion d'erreur via THROW.

▶ Voir la solution 
CREATE OR ALTER PROCEDURE dbo.passer_commande
    @client INT, @produit INT, @qte INT
AS
BEGIN
    SET NOCOUNT ON;
    DECLARE @stock INT, @total DECIMAL(10,2);
    SELECT @stock = stock FROM produits WHERE id = @produit;
    IF @stock < @qte
        THROW 50001, 'Stock insuffisant pour cette commande.', 1;
    SET @total = dbo.prix_final(@client, @produit) * @qte;
    INSERT INTO commandes(client_id,produit_id,quantite,prix_total) VALUES(@client,@produit,@qte,@total);
    UPDATE produits SET stock = stock - @qte WHERE id = @produit;
    PRINT 'Commande validée. Total: ' + CAST(@total AS NVARCHAR) + ' EUR';
END;
GO

EXEC dbo.passer_commande 1, 2, 3;
SELECT * FROM commandes;
TP 04

Trigger : Bloquer le stock négatif (Statement-Level)

Créez un trigger AFTER UPDATE sur produits qui annule l'opération si un stock devient négatif. Utilisez ROLLBACK TRANSACTION dans le trigger.

▶ Voir la solution 
CREATE OR ALTER TRIGGER trg_stock_negatif
ON produits
AFTER UPDATE
AS
BEGIN
    SET NOCOUNT ON;
    IF EXISTS (SELECT 1 FROM inserted WHERE stock < 0)
    BEGIN
        ROLLBACK TRANSACTION;  -- Annule l'UPDATE
        THROW 50002, 'Le stock ne peut pas être négatif.', 1;
    END;
END;
GO

UPDATE produits SET stock = stock - 100 WHERE id = 2; -- Doit échouer
TP 05

Trigger : Audit des changements de prix

Créez la table audit_prix et un trigger AFTER UPDATE qui l'alimente. Attention : utilisez un JOIN entre inserted et deleted pour comparer ancien et nouveau prix.

▶ Voir la solution 
CREATE TABLE audit_prix (
    id INT IDENTITY(1,1) PRIMARY KEY,
    produit_id INT,
    ancien_prix DECIMAL(10,2),
    nouveau_prix DECIMAL(10,2),
    modifie_par NVARCHAR(100) DEFAULT SYSTEM_USER,
    modifie_le DATETIME2 DEFAULT GETDATE()
);
GO

CREATE OR ALTER TRIGGER trg_audit_prix
ON produits
AFTER UPDATE
AS
BEGIN
    SET NOCOUNT ON;
    INSERT INTO audit_prix(produit_id, ancien_prix, nouveau_prix)
    SELECT i.id, d.prix, i.prix
    FROM inserted i
    INNER JOIN deleted d ON i.id = d.id
    WHERE i.prix <> d.prix;  -- N'insère que si le prix a réellement changé
END;
GO

UPDATE produits SET prix = 1350.00 WHERE id = 1;
SELECT * FROM audit_prix;
TP 06

Fonction Table Valued : Valeur du stock

Créez une TVF (Table-Valued Function) dbo.valeur_stock(@categorie) qui retourne une ligne par produit avec sa valeur en stock (prix × stock).

▶ Voir la solution 
CREATE OR ALTER FUNCTION dbo.valeur_stock(@categorie NVARCHAR(50))
RETURNS TABLE
AS
RETURN (
    SELECT nom, prix, stock, ROUND(prix * stock, 2) AS valeur_totale
    FROM produits
    WHERE categorie = @categorie
);
GO

SELECT * FROM dbo.valeur_stock(N'Informatique');
SELECT SUM(valeur_totale) AS total FROM dbo.valeur_stock(N'Accessoires');
TP 07

Trigger : Points fidélité automatiques

Créez un trigger AFTER INSERT sur commandes qui met à jour les points de fidélité de tous les clients concernés en une seule requête basée sur inserted.

▶ Voir la solution 
CREATE OR ALTER TRIGGER trg_points_fidelite
ON commandes
AFTER INSERT
AS
BEGIN
    SET NOCOUNT ON;
    UPDATE c
    SET c.points_fidelite = c.points_fidelite + ROUND(i.prix_total, 0)
    FROM clients c
    INNER JOIN inserted i ON c.id = i.client_id;
    -- Ce UPDATE est SET-BASED : il traite toutes les lignes de "inserted" en même temps.
END;
GO

EXEC dbo.passer_commande 2, 3, 1;
SELECT id, nom, points_fidelite FROM clients WHERE id = 2;
TP 08

Procédure : Réapprovisionner le stock

Créez dbo.reapprovisionner @produit, @qte avec validation et message de confirmation.

▶ Voir la solution 
CREATE OR ALTER PROCEDURE dbo.reapprovisionner @produit INT, @qte INT
AS
BEGIN
    SET NOCOUNT ON;
    IF @qte <= 0 THROW 50003, 'La quantité doit être positive.', 1;
    DECLARE @nom NVARCHAR(100), @avant INT;
    SELECT @nom = nom, @avant = stock FROM produits WHERE id = @produit;
    UPDATE produits SET stock = stock + @qte WHERE id = @produit;
    PRINT N'Réappro OK: ' + @nom + N' — ' + CAST(@avant AS NVARCHAR) + N' → ' + CAST(@avant + @qte AS NVARCHAR) + N' unités';
END;
GO

EXEC dbo.reapprovisionner 4, 10;
EXEC dbo.reapprovisionner 1, -5; -- Doit échouer
TP 09

Procédure : Historique client (TVF intégrée)

Créez une procédure dbo.historique_client @id qui retourne l'historique complet d'un client (produit, quantité, total, date) en utilisant un SELECT avec JOIN.

▶ Voir la solution 
CREATE OR ALTER PROCEDURE dbo.historique_client @id INT
AS
BEGIN
    SET NOCOUNT ON;
    SELECT
        p.nom AS produit,
        c.quantite,
        c.prix_total AS total,
        c.date_cmd
    FROM commandes c
    INNER JOIN produits p ON p.id = c.produit_id
    WHERE c.client_id = @id
    ORDER BY c.date_cmd DESC;
END;
GO

EXEC dbo.historique_client 1;
TP 10

Trigger : Protéger les commandes récentes

Créez un trigger INSTEAD OF DELETE sur commandes qui bloque la suppression des commandes de moins de 30 jours et journalise la tentative.

▶ Voir la solution 
CREATE TABLE tentatives_suppression (
    id INT IDENTITY(1,1) PRIMARY KEY,
    commande_id INT,
    tente_le DATETIME2 DEFAULT GETDATE()
);
GO

CREATE OR ALTER TRIGGER trg_protect_commandes
ON commandes
INSTEAD OF DELETE  -- Intercepte le DELETE avant qu'il ne se passe
AS
BEGIN
    SET NOCOUNT ON;
    -- Insérer dans le journal les commandes récentes qu'on essaie de supprimer
    INSERT INTO tentatives_suppression(commande_id)
    SELECT id FROM deleted WHERE date_cmd > DATEADD(DAY, -30, GETDATE());

    -- Supprimer UNIQUEMENT les commandes de plus de 30 jours
    DELETE c FROM commandes c
    INNER JOIN deleted d ON c.id = d.id
    WHERE d.date_cmd <= DATEADD(DAY, -30, GETDATE());
END;
GO

DELETE FROM commandes WHERE id = 1;
SELECT * FROM tentatives_suppression;
