Préparation

Installation de SQL Server

Windows

1. Téléchargez SQL Server Developer Edition (gratuite pour apprendre) sur microsoft.com.

2. Lancez l'installation avec l'option "Basic" pour une installation rapide. Le port par défaut est 1433.

3. Téléchargez ensuite SQL Server Management Studio (SSMS) depuis aka.ms/ssmsfullsetup. C'est l'outil graphique officiel.

Linux (Ubuntu)

curl -fsSL https://packages.microsoft.com/keys/microsoft.asc | sudo gpg --dearmor -o /usr/share/keyrings/microsoft-prod.gpg
curl https://packages.microsoft.com/config/ubuntu/22.04/mssql-server-2022.list | sudo tee /etc/apt/sources.list.d/mssql-server-2022.list
sudo apt-get update
sudo apt-get install -y mssql-server
sudo /opt/mssql/bin/mssql-conf setup

Pour les outils en ligne de commande (sqlcmd) :

sudo apt-get install -y mssql-tools18 unixodbc-dev
echo 'export PATH="$PATH:/opt/mssql-tools18/bin"' >> ~/.bashrc
source ~/.bashrc

macOS

SQL Server ne tourne pas nativement sur macOS. La solution officielle est de l'utiliser via Docker :

docker pull mcr.microsoft.com/mssql/server:2022-latest
docker run -e "ACCEPT_EULA=Y" -e "MSSQL_SA_PASSWORD=VotreMotDePasse!1" \
   -p 1433:1433 --name sqlserver -d mcr.microsoft.com/mssql/server:2022-latest

Utilisez ensuite Azure Data Studio (aussi disponible sur Windows et Linux) comme client graphique. Téléchargez-le sur aka.ms/azuredatastudio.

Interface graphique (Client SQL)

  • SSMS (SQL Server Management Studio) : L'outil de référence, très complet mais uniquement disponible sur Windows. Affiche les plans d'exécution graphiques.
  • Azure Data Studio (Recommandé) : Multi-plateforme (Windows, Mac, Linux), moderne et léger. Extension IntelliSense pour T-SQL incluse.
  • DBeaver : Client universel, compatible SQL Server via le driver JDBC.

Connexion : Serveur localhost ou 127.0.0.1,1433, Login : sa, Mot de passe : celui défini lors de l'installation.

Notions de base pour les habitués de MySQL/PostgreSQL

  • GO n'est pas du T-SQL : C'est une commande du client (SSMS/sqlcmd). Elle sépare les batches. Vous devez parfois recréer le contexte (USE ma_base; GO) après un GO.
  • IDENTITY au lieu d'AUTO_INCREMENT/SERIAL : id INT IDENTITY(1,1) PRIMARY KEY (commence à 1, incrément de 1).
  • VARCHAR vs NVARCHAR : NVARCHAR supporte les caractères Unicode (accents, emojis). Utilisez NVARCHAR pour les textes utilisateur.
  • TRY...CATCH au lieu de DECLARE HANDLER : La gestion d'erreur en T-SQL est très similaire aux exceptions Java/C#.
  • Bases système : Ne touchez pas à master, model, msdb et tempdb. Ce sont les bases système de SQL Server.
